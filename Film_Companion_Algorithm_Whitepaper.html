1 · Overview

Film Companion is powered by two distinct AI engines that work in concert. Both feed from a single proprietary user model — the TasteVector — which gives us a defensible cross-product moat no competitor (Bumble, Hinge, Letterboxd) currently has.

ENGINE A
People Matchmaking
"Who should I meet?" — Combines deterministic hard filters with GPT-4o ranking and natural-language explanations.
ENGINE B
Movie Recommendation
"What should I watch?" — A multi-dimensional taste vector scored against TMDB's 1M+ catalogue using cosine similarity.

2 · People Matchmaking

A 3-step pipeline. Average latency: 3–8 s on cache miss, < 50 ms on cache hit.

STEP 1
Hard Filters
Deterministic rules narrow ~35 candidates → ~17 valid ones.
~5 ms · 100% rule-based
STEP 2
AI Scoring
Batched GPT-4o call ranks the filtered pool and explains each match.
3–8 s · ~$0.001/req
STEP 3
Cache & Serve
Results cached by profile hash. Auto-invalidates on profile change.
Cache hit < 50 ms

2.1 Hard Filters (always applied)

FilterLogic
Mode compatibilityDate users see only Date users; Buddy sees only Buddy. Always strict.
Gender / Partner preferenceAlways strict, mutual: A wants Women → B must be Female and B wants Men.
Age rangeConfigurable 18–60 default. Supports "exclusive" + 5-year expand fallback.
Languages spokenMulti-select with configurable strictness.
Relationship intentCasual / Friendship / Serious / Exploring.
Film languages, Genres, OTT vs TheatreMulti-select; honour user-selected exclusivity.
Lifestyle (smoking, drinking, religion, food, diet)Honour user-selected exclusivity per attribute.

Each filter supports three strictness modes:

  • Hard reject — exclusive=true, expandIfRunOut=false
  • Prefer strict, expand if pool empty — exclusive=true, expandIfRunOut=true
  • Soft preference — exclusive=false

2.2 AI Scoring with GPT-4o

The filtered ~17 candidates are sent to gpt-4o in a single batched request. The model receives both profiles in full and returns a ranked top 15:

{
  "user_id": "user_abc123",
  "match_level": "Perfect Match | Great Match | Good Match | Potential Match",
  "explanation": "You both share a deep love for Christopher Nolan's mind-bending films and rate slow-burn dramas highly. Priyanka's top 5 includes Inception and Parasite — exactly your vibe.",
  "shared_interests": ["Sci-Fi", "Nolan films", "Slow-burn dramas"],
  "compatibility_score": 87
}

The AI uses dynamic weighting (not fixed) across these signals:

  • Movie genre overlap
  • Favourite movies similarity (Top 5)
  • Liked actors & directors
  • Film & spoken language preferences
  • Viewing habits (OTT vs Theatre, frequency)
  • Lifestyle compatibility
  • Relationship intent alignment
  • Personality match inferred from movie taste

2.3 Deterministic Fallback (LLM unavailable)

If the LLM call fails or the key is missing, we drop to a simple deterministic scorer so the service never breaks:

// Fallback formula
score = (genre_overlap     × 10)
      + (swipe_genre_overlap × 15)
      + (top_movie_overlap   × 25)

if score ≥ 50  → "Great Match"
if score ≥ 30  → "Good Match"
else         → "Potential Match"

3 · Movie Recommendation

The technically differentiated piece — a proprietary high-dimensional Taste Vector built from every user signal, scored against TMDB's catalogue using cosine similarity.

Reason tagging

When a user likes a movie they can optionally tag the reason — "story", "acting", "visuals", "music", "emotional", "entertaining", "thoughtful". These add bonus quality signals (e.g. tagging "story" boosts quality_story_lover, which later +5% boosts dramas/thrillers/mysteries in the feed).

3.4 Scoring a movie

// 1. Vector similarity
similarity = cosine_similarity(user_taste_vector, movie_vector)
score      = (similarity + 1) / 2      // normalised to [0, 1]

// 2. Quality boost
if rating ≥ 7.5 and votes ≥ 1000:   score ×= 1.15
elif rating ≥ 7.0 and votes ≥ 500: score ×= 1.08

// 3. Language priority boost
if primary_language:   score ×= 1.25   // user explicitly selected
elif secondary_language: score ×= 1.10   // inferred from spoken/top movies
elif related_language:   score ×= 1.00   // e.g. Telugu → Tamil, Malayalam, Kannada, Hindi

// 4. Negative-pattern penalty
if matches "skipped" genres:    score ×= 0.90

// 5. Reason-quality boost
"story lover"   + drama/thriller     → ×1.05
"visuals lover" + action/sci-fi      → ×1.05
"emotional"     + drama/romance       → ×1.05

// 6. Cold-start boost (first 10 swipes)
if popularity > 50:               score ×= 1.05

// 7. Personalisation noise — ±15% per-user variance
score ×= random(0.85, 1.15)

// 8. Final clamp to [0, 1]
final = min(score, 1.0)

3.5 Smart discovery tactics

  • Indian-language affinity graph — A Telugu speaker is automatically also offered Tamil/Malayalam/Kannada/Hindi titles without an explicit filter.
  • Score bracketing — Movies within 10% of each other are shuffled so two similar-taste users never see identical lists.
  • Vector normalisation — After every update, the vector is normalised to unit length to prevent runaway weights.
  • Hash-keyed caching — Profile-hash invalidates the cache on any meaningful profile change.

5 · Why this is defensible

Talking points you can use directly with investors:

01
Dual-engine architecture
Most dating apps use cosine sim on demographics. We layer GPT-4o on top of strict filters so every match comes with a contextual, human-readable explanation users actually read.
02
Compounding taste graph
Every swipe enriches 15+ vector dimensions. Two months in, the model is too high-dimensional to clone without our swipe history.
03
Cross-product synergy
The same TasteVector powers both who you match with and what you watch. No competitor (Bumble, Hinge, Letterboxd) does both.
04
Cold-start solved
Even a brand-new user with zero swipes gets meaningful recommendations from Top-5 movies + genres + languages + Tina onboarding chat.
05
India-first language graph
Intelligently bridges related Indian languages (Telugu↔Tamil↔Malayalam↔Kannada↔Hindi) — a competitive moat in our home market.
06
Negative learning
We learn from what users skip, not just like. Reduces echo chambers and surfaces more diverse content over time.
07
LLM cost-controlled
Hard filters cut candidates 35 → 17 before GPT-4o is called. ~$0.001 per match request; cache hits cost zero.
08
Graceful degradation
Deterministic fallback scorer kicks in if the LLM is unavailable. Service uptime is decoupled from LLM-provider uptime.
